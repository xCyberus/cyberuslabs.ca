Hercules

Smart Fitness Hardware Control Platform

An experimental Cyberus Labs project exploring how to restore direct control over app-dependent fitness hardware after the original software ecosystem became unavailable.

01 / The Problem

Useful hardware became dependent on software that no longer worked.

The fitness machine originally relied on an app and service ecosystem for key smart-control behavior. When that supporting software became unavailable or unusable, the hardware was still physically functional, but important control functionality was effectively stranded.

The engineering question became direct and practical: could the machine be controlled without the original software stack?

02 / Investigation

Finding the control path without documentation.

The first challenge was understanding how the Android-based controller actually communicated with the machine. The investigation involved inspecting the original application at a high level, identifying that communication did not use a typical USB endpoint, locating the hardware serial path, observing command/response behavior, and testing direct communication.

03 / Breakthrough

Turning observed commands into direct hardware control.

Once the control path was identified, direct serial commands were successfully used to control the machine. The proof-of-concept recovered enough command behavior to operate core machine functions and read live state information.

04 / Prototype

A custom control interface built around the recovered protocol.

A .NET MAUI Android prototype was built to provide direct control over the machine. Implemented areas included Free Lift mode, start/stop control, left/right resistance control, resistance linking and unlinking, and telemetry display.

Additional training concepts were explored, including structured modes, exercise flows, and plan-oriented workout ideas. These remained prototype and planning work rather than a completed commercial product.

05 / Current Status

The core technical question was answered.

Hercules is currently paused and may not be continued. The project successfully demonstrated direct communication with the machine, software-driven resistance control, start/stop operation, and telemetry access. Further productization and feature development were not completed.

The technical proof-of-concept succeeded: the machine could be controlled independently of the original app ecosystem.

Direct Control — Proven Telemetry — Proven Custom UI — Prototype Productization — Not Completed

06 / Takeaway

Reverse-engineering enough of a closed system to make the hardware useful again.

Hercules demonstrates reverse engineering, undocumented system analysis, hardware/software integration, serial communication, protocol analysis, debugging, Android / .NET MAUI development, and translating low-level control into a usable interface.
